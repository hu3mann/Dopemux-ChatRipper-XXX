# Deep-research targets — chatgpt-web — Output B

**Auditor:** chatgpt-web · **Model/runner:** GPT-6 Astra Pro in ChatGPT · **Date:** 2026-10-20.

**Knowledge cutoff:** UNKNOWN/not exposed in this session. Current primary-source checks are recorded with URLs in the companion `report-chatgpt-web.md`, Report §3.15. This document proposes research; it does not claim that the studies, probes, benchmarks, or implementation tests below have been performed.

The 55 targets below are grounded in the supplied ZIP and linked to the report's F01–F38 findings. Source types identify evidence to obtain in a later authorized investigation. Unbundled repository bodies, real datasets, device captures, installed runtimes, and workflow results remain UNKNOWN until supplied or measured. A prior automated review or an upstream project's feature claim should not serve as the only oracle.

## How to use the priorities

- **P0:** resolve before freezing the affected contract or enabling the dependent high-consequence operation. This does not mean all P0 work must finish before any local development.
- **P1:** complete before shipping the corresponding feature or completing its named phase.
- **P2:** investigate after the baseline works, before adopting an optional enhancement.
- **P3:** exploratory work with no committed feature dependency.

**Effort** is relative investigation scope, not a schedule promise: **S** = focused document/contract review or small spike; **M** = several sources plus a bounded empirical study; **L** = corpus creation, multi-component experiments, or specialist validation.

Every completed target should produce a decision, an evidence bundle, limitations/UNKNOWNs, and a reproducible verification method. Fixes should not be justified solely by a library name, leaderboard, coverage percentage, or successful happy-path demonstration.
