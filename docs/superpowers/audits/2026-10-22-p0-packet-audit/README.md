| `PROMPT-readonly-preamble.md` | Harness constraints prepended to the cmd lanes' prompts: no write/edit/shell tools, no reads outside this directory, cite `out/HARNESS-FACTS.md`, deliver both files inline between `=== FILE:` / `=== END ===` markers. |
| `make_readonly_prompts.py` | Generates `PROMPT-<auditor>.readonly.md` = preamble + wrapper with the full-tool "## Access" section replaced by the read-only one. `--check` verifies the generated files are current. |
| `extract_deliverables.py` | Splits a `cmd -p --output-format json` NDJSON stream into `<auditor>.final.md`, `<auditor>.usage.txt` and the two deliverables; exit 0 = both written, 4 = missing block(s), 3 = no final text. |
| `out/HARNESS-FACTS.md` | Supervisor-computed facts for auditors that cannot run tools: repo HEADs, per-file sha256 and line counts, toolchain versions. Auditors must cite these as harness-supplied. |
| `out/` | All auditor outputs and run records. `_run-<auditor>.txt` holds requested model/effort, command, times, exit code. Failed attempts are kept under `out/_attempt1-cmd-failed/` and `out/_attempt2-cmd-failed/` (the latter includes the permission smokes). |

Exact runner invocations (as embedded in `run_audits.sh`):

## Acceptance checks for each auditor output

1. `out/report-<auditor>.md` starts with the four identity lines and has one `Packet verdict:` line.
2. The findings table parses (`build_matrix.py --check` reports 0 malformed rows for that auditor).
3. Every CONFIRMED row cites `packet:`, `spec:`, `dnh:` or `bundle:`.
4. `out/preapproval-<auditor>.md` has the `| ID | Check | How to verify | Blocking? |` table.
5. `_gitstatus-pre` and `_gitstatus-post` for the run are identical.

Failing 1–4 means the output is kept but marked PARTIAL in the status table; failing 5 stops everything until the diff is explained.
